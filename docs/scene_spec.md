# シーン・表示追加仕様

作成日: 2026-08-03(本体仕様書 [spec.md](./spec.md) の補足)

## 1. 部屋(VR空間)の形状

表示空間は、**ディスプレイの表示領域(矩形)をそのまま奥方向(Z負方向)へ押し出したボックス状の部屋**とする。

- 部屋の開口部 = ディスプレイ表示面(`Z = 0`)。開口部の幅・高さは表示領域の物理サイズと一致させる
- **部屋の奥行き = ディスプレイ表示幅と同一**(`depth = W`)
- 部屋の内壁(左右・上下・奥)を描画し、「画面の奥に箱型の部屋がある」見え方を作る

```text
表示幅 W、表示高さ H のとき:
  部屋 = 幅 W × 高さ H × 奥行き W のボックス
  開口部: Z = 0(ディスプレイ面)
  奥壁 : Z = -W
```

壁面には奥行き知覚を助けるテクスチャ(格子・タイル等)を用いる。

## 2. アバター

- 部屋の内部に、**部屋(=表示サイズ)に収まる程度の大きさ**のアバターを1体配置する
- アバターの高さは部屋の高さ H の 60〜80% 程度を目安にスケーリングする(モデル実寸に関わらず部屋基準で正規化)
- 静止(Idle)アニメーションを常時ループ再生する。追加モーションは後続で拡張
- 使用アセットは [assets.md](./assets.md) の方針に従う(MVP: RobotExpressive.glb / CC0)

## 3. 表示サイズと画面適応

### 3.1 スマートフォン(主対象)

- 全画面表示とし、画面全体を「表示領域」とする
- 表示領域の物理サイズ(幅W・高さH)は端末の画面物理寸法から求め、部屋の寸法に直結させる

### 3.2 PC(ブラウザ・任意ウィンドウサイズ)

- Webアプリのため、カメラ付きPCでも動作させる
- **初期実装ではアスペクト比を固定(スマホ縦画面相当、例 9:19.5 または 9:16)し、スケールのみ可変とする**
  - ブラウザウィンドウ内に固定比率の表示領域をレターボックス配置(中央寄せ、余白は黒等)
  - 表示領域のCSSピクセルサイズから物理サイズを概算(96dpi基準+ユーザー校正で補正)し、部屋寸法・投影計算に使用
- 任意アスペクト比への完全対応は将来拡張とする。部屋の寸法規則(奥行き=幅)は表示領域サイズから常に導出されるため、拡張時も規則自体は不変

### 3.3 寸法の一元管理

`DisplayCalibration` モジュールが表示領域の物理寸法(W, H)を一元管理し、以下すべてが同じ値を参照する。

- off-axis projection のディスプレイ四隅(`±W/2, ±H/2`)
- 部屋ボックスの寸法(W × H × W)
- アバターのスケール(H基準)

これにより画面サイズ・向きの変更時は W, H の更新だけで全体が追従する。

## 4. 配布・インストール(GitHub Pages + PWA)

- アプリは GitHub Pages(HTTPS)で配信する
- **PWA対応(Web App Manifest + Service Worker)を行い、ブラウザの「ホーム画面に追加」からインストール可能にする**
  - Android/Chrome: インストールプロンプト表示可
  - iOS/Safari: 「ホーム画面に追加」で全画面起動(standalone表示)
  - アプリストア不要・URLを開くだけでも利用可能(仕様書 §2 のインストール不要要件と両立)
- Service Worker によるアセットキャッシュでオフライン起動にも対応可能(カメラ処理は元々端末内完結)
