# ヘッドトラッキングVR Webアプリ 仕様書

## 1. 概要

スマートフォンまたはタブレットのインカメラで観察者の顔を検出し、ディスプレイに対する観察者の目の3次元位置を推定する。その位置を基準としてVR空間をリアルタイムに再レンダリングし、ディスプレイの奥に仮想空間が存在するような運動視差表示を実現する。

本方式は、観察者の顔の向きに合わせて仮想カメラを単純に回転させる方式ではない。観察者、物理ディスプレイ、仮想空間を同一の座標系で扱い、観察者の目とディスプレイ四隅との位置関係から非対称透視投影（off-axis projection）を計算する。

## 2. 目的

- アプリをインストールせず、スマートフォンのWebブラウザから利用可能にする。
- 観察者が左右・上下・前後に移動した際、ディスプレイを仮想空間への窓として自然に覗き込める表示を実現する。
- 複数の顔が検出された場合も、表示対象となる観察者を安定して選択・追跡する。
- 顔検出の揺れや一時的な検出失敗による映像の振動・跳躍を抑える。

## 3. 想定動作環境

- インカメラを搭載したスマートフォンまたはタブレット
- `getUserMedia()`、WebGL 2.0を利用できるモバイルブラウザ
- HTTPSで配信されるWebアプリケーション
- 縦画面・横画面の両方に対応することが望ましい

WebXRは必須としない。本アプリでは実空間の平面検出を行わず、インカメラ映像から得た観察者位置と、WebGL上の仮想空間を組み合わせる。

## 4. 基本動作

1. ユーザーがWebページを開く。
2. アプリがインカメラの使用許可を要求する。
3. カメラ映像から1人以上の顔ランドマークを検出する。
4. ターゲットとなる顔を選択する。
5. ターゲットの左右の目の位置、頭部姿勢および顔の見かけの大きさから、カメラ座標系における目の3次元位置を推定する。
6. カメラ位置とディスプレイ位置の差を補正し、目の位置をディスプレイ座標系へ変換する。
7. 目の位置と物理ディスプレイ四隅から非対称投影行列を計算する。
8. 投影行列を使用してVR空間を再レンダリングする。
9. 顔が移動するたびに手順5～8を繰り返す。

## 5. 座標系

ディスプレイ中心を原点とする右手系または左手系の統一座標を定義する。利用する3Dエンジンの規約に合わせて実装するが、内部で一貫性を保つこと。

概念上は次のように定義する。

- X軸：ディスプレイ水平方向。右を正とする。
- Y軸：ディスプレイ垂直方向。上を正とする。
- Z軸：ディスプレイから観察者側を正とする。
- ディスプレイ面：`Z = 0`
- VR空間：原則として`Z < 0`
- 観察者の目：`E = (Ex, Ey, Ez)`、通常は`Ez > 0`

ディスプレイの物理範囲を次の値で表す。

- 左端：`xLeft`
- 右端：`xRight`
- 下端：`yBottom`
- 上端：`yTop`

これらの値にはCSSピクセルではなく、物理寸法に相当する統一スケールを使用する。

## 6. 観察者位置の推定

### 6.1 推定対象

投影計算に使用する主要値は、眼球の注視方向ではなく、ディスプレイ座標系における観察者の目の位置とする。

基本視点は左右の目の中点とする。

`E = (Eleft + Eright) / 2`

必要に応じて、顔ランドマークから推定した眼球中心または頭部モデル上の代表点を使用する。

### 6.2 使用情報

- 左右の目、鼻、口、顔輪郭などの顔ランドマーク
- 顔のバウンディングボックス
- 左右の瞳孔間または目頭・目尻間の画像上距離
- 頭部の回転姿勢
- インカメラの画角または内部パラメータ
- カメラとディスプレイ中心との物理的位置差
- ディスプレイの物理寸法
- 端末の画面方向

### 6.3 距離推定

単眼カメラであるため、絶対距離は顔モデルの基準寸法を使って推定する。初期実装では、左右の目の間隔または顔幅の見かけの大きさを距離推定に使用してよい。

精度向上のため、初回利用時にユーザーを既知または想定距離へ誘導して校正できることが望ましい。

### 6.4 カメラ座標からディスプレイ座標への変換

インカメラは通常ディスプレイ中心と一致しないため、カメラ座標系で推定した目の位置を、そのまま投影計算へ使用してはならない。

以下を含む変換を適用する。

- カメラとディスプレイ中心の平行移動
- 端末固有のカメラ取り付け角度補正
- 縦画面・横画面に対応する軸変換
- カメラ映像のミラー表示と計算座標の分離

## 7. 非対称透視投影

### 7.1 基本方針

仮想カメラを観察者の目の位置へ置き、目から物理ディスプレイ四隅へ向かう視線を投影錐台の境界とする。

目の位置がディスプレイ正面中央から外れた場合、左右または上下が非対称な視錐台を生成する。レンダリング画像はディスプレイ正面から見ると歪んで見える場合があるが、推定された観察位置からは正しい透視像として見えること。

### 7.2 投影範囲

near距離を`n`、観察者からディスプレイ面までの距離を`Ez`とした場合、概念上の投影範囲を次のように求める。

```text
left   = n * (xLeft   - Ex) / Ez
right  = n * (xRight  - Ex) / Ez
bottom = n * (yBottom - Ey) / Ez
top    = n * (yTop    - Ey) / Ez
```

実装時は使用する3Dエンジンの座標方向、カメラ前方軸、投影行列の引数順序およびクリップ空間の規約に合わせて符号を調整する。

### 7.3 レンダリング更新

顔の推定結果が更新されるたびに、以下を更新する。

- 仮想カメラの位置
- 仮想カメラのビュー行列
- 非対称投影行列
- 投影行列の逆行列など、レンダリングエンジンが必要とする派生値

単純な`lookAt()`と対称FOVによる透視投影だけで代用してはならない。

## 8. 複数顔の選択と追跡

### 8.1 基本方針

ターゲット未選択時は、推定距離が最も近い顔を選択する。一度ターゲットを選択した後は、別の顔が検出されても同じ顔を継続追跡する。

### 8.2 初期選択

次の情報を組み合わせて各顔の距離を推定し、最も近い顔を選択する。

- 両目間隔の画像上サイズ
- 顔バウンディングボックスの大きさ
- 3Dランドマークの推定Z値
- 頭部姿勢による見かけサイズの補正

初期実装では顔サイズを主指標としてよいが、横向きの顔を過度に遠いと判定しないよう補正する。

### 8.3 同一顔の追跡

前フレームのターゲットと現在の検出顔を、以下の情報から対応付ける。

- 顔中心位置
- 顔の大きさ
- ランドマーク配置
- 移動速度と予測位置
- 検出ライブラリが安定したトラッキングIDを提供する場合はそのID

本人識別を目的とする顔認証は必須としない。また、生体認証用の顔特徴量を保存しない。

### 8.4 一時的な検出喪失

- 顔を一時的に検出できなくても、直ちに別の顔へ切り替えない。
- 0.5～1.0秒程度は直前の位置および速度から視点を予測する。
- 同じ位置付近で顔を再検出した場合は、同一ターゲットとして追跡を再開する。
- タイムアウト後はターゲットを解除し、最も近い顔を再選択する。

### 8.5 切り替え抑制

別の顔への自動切り替えにはヒステリシスを設ける。

切り替え条件の例：

- 現在のターゲットを規定時間以上見失った。
- 新しい顔が現在のターゲットより20～30%以上近い状態を0.5秒以上維持した。
- ユーザーが画面操作で明示的にターゲットを変更した。

距離順位がフレームごとにわずかに変化しただけでは切り替えない。

## 9. 平滑化と遅延対策

### 9.1 平滑化

目位置の推定値にローパスフィルター、One Euro Filter、Kalman Filterなどを適用し、ランドマーク検出の細かな振動を抑える。

位置と回転は必要に応じて別々のパラメータで平滑化する。強すぎる平滑化は表示遅延を発生させるため、速度に応じて平滑化強度を変える方式が望ましい。

### 9.2 予測

検出・推論・描画による遅延を補うため、直近の位置と速度から描画時点の目位置を短時間予測してよい。予測時間には上限を設け、急激な誤推定を防止する。

### 9.3 目標性能

- 描画：目標60 fps、最低30 fps
- 顔推定：目標30 fps以上。端末性能に応じて入力解像度を調整する。
- カメラ入力から描画反映までの総遅延：目標50 ms程度、許容上限100 ms程度
- 顔静止時にVR空間が目立って振動しないこと

## 10. Webアプリ構成案

### 10.1 推奨技術

- TypeScript
- `getUserMedia()`によるインカメラ取得
- MediaPipe Face Landmarkerなどによる顔ランドマーク検出
- Three.jsまたはBabylon.jsによる3D描画
- WebGL 2.0
- 必要に応じてWASMまたはWebGPUによる推論高速化
- PWA対応は任意

### 10.2 処理モジュール

```text
CameraInput
  └─ インカメラ映像取得、解像度・画面方向管理

FaceDetector
  └─ 複数顔ランドマーク検出

TargetTracker
  └─ 最接近顔の初期選択、同一顔追跡、再選択

EyePoseEstimator
  └─ カメラ座標系における目の3次元位置推定

DisplayCalibration
  └─ 画面寸法、カメラ位置、端末方向、ユーザー校正

PoseFilter
  └─ 平滑化、一時喪失時の予測、外れ値除去

OffAxisCamera
  └─ ディスプレイ座標への変換、ビュー・投影行列計算

SceneRenderer
  └─ VR空間の生成とリアルタイム描画

AppUI
  └─ 権限要求、校正、状態表示、設定
```

## 11. UI要件

最低限、以下を提供する。

- カメラ権限要求画面
- 顔検出・追跡状態の表示
- 基準位置または距離を設定する校正機能
- トラッキングの再初期化ボタン
- デバッグ表示のON/OFF

デバッグ表示には以下を含めるとよい。

- 検出顔のバウンディングボックス
- 選択中ターゲットの識別表示
- 推定目位置`Ex, Ey, Ez`
- 推定距離
- FPSおよび推論時間
- 投影錐台または仮想カメラ位置の簡易表示

通常動作時はインカメラ映像をユーザー画面へ表示しなくてよい。

## 12. 例外処理

- 顔が検出されない場合は、最後の安定位置を短時間維持した後、正面中央の既定視点へ緩やかに戻す。
- 顔位置が物理的に不可能な値となった場合は外れ値として破棄する。
- カメラ権限が拒否された場合は、設定方法を案内し、VR空間を既定視点で表示する。
- 端末回転を検出した場合は、カメラ入力、画面寸法、カメラオフセットおよび座標変換を再設定する。
- タブのバックグラウンド移行・復帰後にカメラと推論処理を安全に再開する。

## 13. プライバシー要件

- カメラ画像および顔ランドマーク処理は原則として端末内で完結させる。
- カメラ画像をサーバーへ送信しない。
- 顔画像、顔特徴量、生体識別情報を保存しない。
- 録画機能は実装しない。ただし別途明示された要件がある場合を除く。
- カメラが使用中であることをUI上で明確に示す。

## 14. 制約

- 通常の単眼ディスプレイであるため、正しい透視像を提供できるのは原則として1人・1視点である。
- 左右の目へ別画像を提示しないため、両眼視差による立体視は提供しない。主な奥行き手掛かりは運動視差、透視投影、遮蔽、陰影とする。
- 単眼インカメラによる絶対距離推定には誤差がある。
- 端末ごとのカメラ画角、画面寸法、カメラ位置差が精度に影響する。
- 暗所、逆光、顔の大きな遮蔽、極端な顔角度では追跡性能が低下する。

## 15. MVP範囲

初期試作では以下を実装する。

1. インカメラ映像取得
2. 最大3人程度の顔ランドマーク検出
3. 最も近い顔の初期選択
4. 同一顔の継続追跡
5. 左右の目の中点による視点推定
6. 顔サイズによる概算距離推定
7. 目位置の平滑化
8. Three.jsによる簡単なVRルーム表示
9. off-axis projectionによる視点連動描画
10. 顔喪失時の短時間維持と再選択
11. 推定値とFPSのデバッグ表示

MVPでは端末固有の厳密なカメラ・ディスプレイ校正を省略し、代表的な端末寸法またはユーザー校正値で代用してよい。

## 16. 将来拡張

- 端末モデル別の画面寸法・カメラ位置データベース
- ユーザーごとの瞳孔間距離または顔寸法校正
- 虹彩ランドマークによる注視点推定
- WebGPUによる推論高速化
- 端末姿勢センサーとのセンサーフュージョン

- VR空間内オブジェクトとの視線・ジェスチャー操作

## 17. 受入条件

- 観察者が正面中央にいる場合、VR空間が通常の正面透視像として表示される。
- 観察者が左右へ移動すると、固定されたディスプレイ越しにVR空間を横から覗き込んだように見える。
- 観察者が上下へ移動すると、VR空間の上側または下側が自然に見える。
- 観察者が前後へ移動すると、ディスプレイの物理範囲を窓とした視野変化が生じる。
- 顔の移動に対して仮想空間全体が不自然に平行移動するのではなく、正しい運動視差が発生する。
- 複数顔の検出中に距離順位がわずかに変化しても、ターゲットが頻繁に切り替わらない。
- ターゲットの顔を短時間見失っても表示が即座に別の人物へ跳ばない。
- ターゲットを規定時間以上見失った場合、最も近い顔を新たなターゲットとして取得できる。
- 通常利用時にカメラ画像または顔情報が端末外へ送信されない。

## 18. 用語

- **Head-coupled perspective**：観察者の頭部位置に応じて表示透視像を変化させる方式。
- **Fish-tank VR**：ディスプレイを仮想空間を覗く窓として扱うVR表示方式。
- **Off-axis projection**：視点が画面中心軸上にない場合に使用する非対称透視投影。
- **Generalized perspective projection**：任意位置の観察者と投影面から透視投影を構成する方法。
- **運動視差**：観察者の移動によって近景と遠景の見え方が異なって変化する奥行き手掛かり。
